GUIDES  /  ELEMENTOR MCP

Connect AI to WordPress

Elementor MCP lets your AI directly control your WordPress site — creating pages, updating layouts, swapping widgets, and rebuilding sections — without manual drag-and-drop. This guide walks you through setup, configuration, and getting the most out of AI-driven page building.

Standard AI integrations with Elementor are limited to generating copy or suggesting layout ideas. The output is text — you still have to drag, drop, and wire everything yourself. Elementor MCP changes that.

MCP (Model Context Protocol) is an open standard that lets AI models call tools exposed by external servers. With the Elementor MCP plugin, your AI client can directly invoke Elementor's builder — creating pages, moving sections, updating widget settings, and applying styles — as structured API calls, not chat suggestions.

◎
What's new about this approach
Instead of copying AI-generated HTML into Elementor, your AI controls Elementor directly. It can list pages, inspect structures, modify containers, and rebuild entire landing pages in a single prompt session.

Prerequisites

Before you begin, make sure the following are in place on your WordPress site.

  • ✓ WordPress installed and accessible
  • ✓ Elementor (free) — Elementor Pro gives access to more widgets and templates
  • ✓ An MCP-compatible AI client (Antigravity, Claude Code, or similar)
  • ✓ The MCP Adapter plugin Required dependency
  • ✓ The Elementor MCP plugin Core plugin

Quickstart

The fastest path from zero to a working AI-controlled Elementor site:

1
Install both plugins Download and activate the MCP Adapter plugin first, then the Elementor MCP plugin from their GitHub Releases pages.
2
Create an application password Go to Users → Profile in WordPress, scroll to Application Passwords, and generate one for your AI client.
3
Generate the MCP config In Settings → EMCP Tools → Connection, click Generate Config and copy the connection string.
4
Paste into your AI client Add the connection string to Antigravity, Claude Code, or any MCP-compatible client, then restart it.
5
Start building Ask your AI to list pages or create a new landing page — Elementor MCP will handle the rest.
💡
Need more detail on any step? The sections below walk through each one in full.

Install plugins

Elementor MCP depends on the MCP Adapter plugin, so you must install that first. Both are installed via your WordPress dashboard as uploaded ZIP files — they are not yet available in the public plugin directory.

1
Download both plugins from GitHub Releases Download the .zip file for the MCP Adapter plugin and the Elementor MCP plugin from their respective GitHub Releases pages. Keep both files ready.
2
Install MCP Adapter first In your WordPress dashboard, go to Plugins → Add Plugin → Upload Plugin. Select the MCP Adapter .zip, click Install Now, then Activate.
3
Install Elementor MCP Repeat the upload step with the Elementor MCP .zip. Install and activate it. You should now see an EMCP Tools entry under Settings.
⚠
Install the MCP Adapter before Elementor MCP. Activating Elementor MCP without the adapter will result in a dependency error.

Create an application password

Your AI client authenticates with WordPress using an Application Password — a scoped, revocable credential that doesn't expose your main admin password.

1
Open your WordPress user profile Go to Users → Profile (or Your Profile).
2
Scroll to Application Passwords Enter a descriptive name (e.g. Elementor MCP — Antigravity) and click Add New Application Password.
3
Copy the generated password WordPress shows the password only once. Copy it immediately — you'll need it in the next step.

Generate the MCP config

With the application password ready, return to Settings → EMCP Tools and switch to the Connection tab. Click Generate Config. This produces a connection string you'll paste into your AI client.

💡
Keep the config tab open after generating. The connection string is shown only once — if you navigate away, you'll need to regenerate a new one.

Connect with Antigravity

Antigravity has native MCP server support, making the connection straightforward.

1
Copy the connection string From the EMCP Tools config screen, copy the full connection string.
2
Add to Antigravity MCP servers Open Antigravity → MCP Servers → Add Server, and paste the connection string.
3
Refresh and enable tools Click Refresh. Antigravity will pull in the available Elementor MCP tools. You can enable or disable individual tools from the tools panel.

Connect with Claude Code

Claude Code reads MCP server definitions from a JSON config file. Paste the Elementor MCP config into your mcp_config.json (or your project's .claude/mcp.json), then restart the editor.

json   ~/.claude/mcp_config.json copy 
{
  "mcpServers": {
    "elementor-mcp": {
      "command": "npx",
      "args": ["-y", "@elementor/mcp-server"],
      "env": {
        "WP_URL": "https://your-site.com",
        "WP_USER": "your-username",
        "WP_APP_PASSWORD": "xxxx xxxx xxxx xxxx xxxx xxxx"
      }
    }
  }
}

After saving, restart Claude Code and run:

bash 
# Verify the MCP server is connected
/mcp list-tools elementor-mcp

Once connected, Claude Code can call any of the Elementor MCP tools — list pages, inspect layouts, create containers, update widgets, and more.

What AI can control

Once connected, your AI has access to the full set of Elementor MCP tools:

Available MCP tools 
# Page operations
list-pages          # list all WordPress pages
create-page         # create a new page
get-page-structure  # inspect a page's element tree
delete-page-content # clear a page's content

# Layout
add-container       # add a flex/grid container
add-flexbox         # add a flexbox section
update-container    # update container settings
move-element        # reorder elements in the tree
duplicate-element   # duplicate any element
remove-element      # delete an element

# Widgets
add-heading         # insert a heading widget
add-text-editor     # insert a text/rich content block
add-image           # insert an image widget
add-button          # insert a CTA button
add-icon-box        # insert icon + text block
update-widget       # update widget settings by ID
find-element        # search for an element by type or content

Writing effective prompts

The most common source of disappointment with AI page builders isn't the tool — it's the prompt. A vague prompt forces the AI to guess the layout, hierarchy, spacing, and style all at once. The results look generic because they are generic: the AI had no direction.

Simple vs. detailed prompts

Too vague

"Create a landing page for a web design agency."

Specific and directive

"Build a landing page for a web design agency. Start with a full-width hero: left-aligned heading ('We build websites that convert'), a subheading in gray, and a green CTA button. Below that, a 3-column icon section showing our services. Then a testimonial row with a dark background. Keep spacing generous — 80px section padding. No stock photography."

◎
The principle: AI follows direction well. It guesses layout poorly. The more structure you define in the prompt, the closer the first draft is to something usable.

What to include in a layout prompt

  • Section order and names (hero, services, testimonials, CTA)
  • Layout per section (1-column, 3-column grid, alternating image-text)
  • Heading copy or placeholder intent
  • Color guidance (dark background, accent color, text color)
  • Spacing preferences (compact, airy, generous)
  • What to exclude (no carousels, no video embeds, no stock images)

Iterating on results

Don't judge the page from the first draft alone. Once the initial structure exists, keep directing your AI rather than starting over. Use follow-up prompts to refine:

Example follow-up prompts 
# Adjust spacing
"Increase the padding on the hero section to 120px top and bottom."

# Swap a widget
"Replace the text block in the services section with three icon boxes."

# Update copy
"Update the hero heading to: 'Strategy. Design. Growth.' in 52px."

# Move sections
"Move the testimonials section above the pricing table."

# Style a button
"Change the CTA button to a dark background with white text and 8px border radius."

Each of these maps directly to an Elementor MCP tool call. Your AI will call the right tool, target the right element by ID, and apply the change — no manual clicking required.

Token distribution — typical turn

Every turn loads the system prompt, accumulated conversation history, MCP tool results, and generates a response. The system prompt is the largest fixed cost — it is paid on every message.

Cost per task type

A post/page query is the cheapest operation — mostly read-only with a small JSON response. Layout fixes involve multiple sequential tool calls. Full page translation is the most expensive, requiring a large page-structure read, LLM processing, and widget-by-widget updates.

Runs achievable per budget

How many operations you can complete at various spend levels. Post queries go furthest; translations consume budget roughly 12× faster than queries.

Security considerations

Giving AI direct write access to a live site introduces risks beyond cosmetic changes. Depending on what you ask it to do, the AI can touch layouts, widget settings, embeds, custom JavaScript, and HTML blocks. AI-generated code can introduce vulnerabilities — especially in custom code widgets.

Recommended precautions

1
Use a staging site for initial testing Run your first Elementor MCP sessions on a staging copy of your site, not production. Most managed WordPress hosts offer one-click staging.
2
Install a security plugin Use a plugin like MalCare, Wordfence, or Solid Security. Run a scan before and after any session where the AI touched custom code, HTML embeds, or script widgets.
3
Review AI-generated custom code If you ask the AI to insert a custom code widget or HTML block, review the output before publishing. AI-generated JavaScript should be treated as untrusted until inspected.
4
Rotate the application password after testing When a project is done or a session ends, revoke the application password from your WordPress profile and generate a new one for the next session.
⚠
Application passwords grant API-level access to your site. Treat them like passwords: don't commit them to version control, don't share them, and revoke them when no longer needed.

SlyTranslate Plugin

SlyTranslate is a WordPress plugin that brings AI-powered content translation directly into your MCP workflow. It exposes translation abilities through the MCP Adapter, so LLM clients like Claude Code can translate posts and pages without leaving the conversation.

SlyTranslate Plugin
AI translation for WordPress posts and pages via MCP. Supports server-side and client-side LLM workflows.
SlyBase/wordpress-slytranslate ↗

Once installed and connected, SlyTranslate exposes three core MCP abilities:

SlyTranslate MCP abilities 
# Discovery
mcp-adapter-discover-abilities   # list all registered translation abilities
mcp-adapter-get-ability-info     # get schema + examples for a specific ability
mcp-adapter-execute-ability      # execute any ability by name with parameters

What's new — v1.9.0-beta.2

Pre-release  Released May 26, 2026  ·  View on GitHub ↗

New features

+
Client-side translation workflow Three new abilities enable LLM-driven translation without requiring a server-side AI connector. The LLM decomposes, translates, and persists content directly:
New abilities 
ai-translate/prepare-client-translation       # decompose one post into labelled units
ai-translate/apply-client-translation         # persist translated units back to the post
ai-translate/prepare-client-translation-bulk  # bulk decompose multiple posts
ai-translate/apply-client-translation-bulk    # bulk persist translated unit packages
◎
This is the workflow used in this session to translate posts. It works without any API key or AI connector configured in WordPress — the connected LLM client does the translation.
+
Cleaner UI in MCP-only setups Server-side translation controls (editor sidebar, list-table actions, TranslatePress editor panel) are now hidden unless an AI connector is actually configured. This prevents non-functional buttons from appearing when only the client-side workflow is in use.

Bug fixes

✓
Clarified translations parameter format Updated descriptions for apply-client-translation and apply-client-translation-bulk to explicitly state that translations must be an array of {id, translated} objects — not an associative object keyed by unit ID. This prevents LLM clients from sending the wrong format.
✓
Output unit property descriptions added Property descriptions are now included in the prepare-client-translation output schema for units. LLM clients can now use the workflow autonomously without needing to call get-ability-info first to understand the output structure.
